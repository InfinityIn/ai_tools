# design-it — дизайн от задачи до проверенного интерфейса

**База:** прочитай установленный `orchestrate/SKILL.md` и используй его роли,
скелет и формат финала. В репозитории база находится в
[`../orchestrate/SKILL.md`](../orchestrate/SKILL.md). Здесь — только профиль дизайна.
Если инструменты делегирования недоступны, выполни этапы последовательно и
отдельно обозначь отсутствие независимого ревью; не выдумывай агентов.

## Границы трёх слоёв

- **A — портфель:** эти переиспользуемые скиллы и общие регламенты ai_tools.
  Стилистические предпочтения авторов — инструменты, не новые общие регламенты.
- **B — проект:** аудитория, продуктовые факты, бренд, существующая дизайн-система,
  стек, токены, контракты и ограничения. Читай уже существующие документы;
  сохраняй устойчивые решения в принятом проектом месте, не в глобальном скилле.
- **C — сессия:** маршрут, распределение работы, итерации и доказательства приёмки.
  Краткий бриф и результаты сохраняй в `.Codex/notes/design-<тема>/` проекта.
  Если проект уже имеет установленный путь заметок, используй его.

## 1. Зафиксируй задачу и исходное состояние

Определи поверхность и режим: новый интерфейс / редизайн / полировка /
только анимация / только аудит. Запиши цель пользователя, основной сценарий,
границы изменения, что сохраняем, доступные фактические тексты и изображения,
размеры экранов и наблюдаемые критерии готовности. При наличии приложения
посмотри его и сними baseline до правок. Отсутствие DESIGN.md не означает
отсутствия сложившегося дизайна.

Используй стек и компоненты проекта. Не добавляй фреймворк, библиотеку анимации,
выдуманные отзывы, показатели или новые функции только ради красивого экрана.
Неясные обратимые детали решай сам и фиксируй; существенный вопрос владельцу
задай прямо в сессии, продолжая независимую работу.

## 2. Выбери маршрут, затем загрузи нужные скиллы

Скиллы установлены соседними каталогами. В исходном ai_tools прикладные скиллы
находятся в `src/skills/<имя>/SKILL.md`; после установки —
`<каталог-установки>/<имя>/SKILL.md`. Перед применением прочитай реальный файл.
Не загружай все пять и все их справочники по умолчанию.

| Задача | Ведущий скилл | Дополнение и выход |
|---|---|---|
| Новый экран, компонент, рабочий интерфейс | `frontend-design` | Концепция, типографика, цвет, композиция; реализация по брифу |
| Публичный сайт, лендинг, портфолио с новым характером | `design-taste-frontend` | Альтернативный арт-директор вместо повторного полного прохода Frontend Design; не применять к dashboard/app UI |
| Существующий интерфейс, точечная полировка, UX/a11y-аудит | `impeccable` с конкретным `critique`, `audit`, `polish`, `adapt` или другим подходящим режимом | Проверка/исправление в заданных границах; audit-only не даёт разрешения редактировать |
| Переходы, жесты, микровзаимодействия, отзывчивость | `emil-design-eng` | Цель движения, частота, easing/duration, прерывание, reduced motion; может рекомендовать отсутствие движения |
| Фактическая проверка результата в браузере | `playwright-cli` | Сценарий, реальные скриншоты, состояния, ошибки; не источник визуального стиля |

Для полного цикла: один арт-директор → реализация → Emil при необходимости →
Impeccable для проверки/полировки → Playwright. Для узкой задачи пропусти
неприменимые этапы. Передавай дочернему скиллу конкретную задачу и контекст:
пустой вызов Impeccable открывает меню, пустой вызов Emil только приветствует.

## 3. Разреши конфликт рекомендаций до реализации

Приоритет: явный запрос владельца → факты, доступность и ограничения проекта →
зафиксированный бриф и выбранное направление → рекомендации текущего скилла.
Согласованный редизайн может заменить старую визуальную систему; полировка её
сохраняет. Один ведущий арт-директор на поверхность, одна система токенов.

Taste содержит жёсткий house style, минимумы изображений и движения. Это его
эстетический профиль, а не универсальные требования. Не нарушай бренд,
reduced-motion, требования к скорости или фактическую правду ради его PASS.
Если профиль несовместим с заданием, выбери Frontend Design/Impeccable и явно
зафиксируй причину. При осознанном исключении сохрани исходный результат
детектора и обоснование; не выдавай исключение за чистый PASS.

Для анимаций реши сначала, нужно ли движение пользователю. Рекомендации Emil
по интенсивности и прерыванию применяй в контексте продукта. Не наращивай
движение для удовлетворения маркетингового минимума Taste на рабочем экране.

## 4. Реализуй и проверь

При делегировании передавай каждому исполнителю выбранный бриф, скилл,
владение файлами и критерий готовности. Сообщи, что он не один в кодовой базе
и должен учитывать чужие правки. Параллельно допустимы независимые разведка
и проверки; один компонент/CSS/токены в каждый момент правит один исполнитель.
Ревьюер получает бриф, текущий diff и способ открыть приложение.

Настрой минимальный воспроизводимый preview в рамках задачи. Проверяй
отрендеренный результат, а не только код или DOM snapshot. Для визуальной
приёмки нужны изображения, даже если Playwright предпочитает текстовые snapshots
для навигации. Используй [references/acceptance.md](references/acceptance.md).

Исправь выявленные дефекты и перепроверь затронутые сценарии. После двух
проходов без измеримого улучшения пересмотри причину/подход; не повторяй
косметические правки ради субъективного совершенства. Успех — исходные критерии
выполнены и нет известных существенных регрессий. Непроверенное обозначь явно.

## Среда и зависимости

- `playwright-cli` — инструкция, CLI и браузер устанавливаются отдельно.
  Проверь доступную версию и `--help`; используй изолированную сессию/профиль
  и закрывай только свой браузер. Не очищай профиль пользователя.
  Если команды нет в PATH, доступен проверенный вариант
  `npx --yes --package @playwright/cli@0.1.22 playwright-cli <команда>`.
- Taste `draw.mjs` работает с Node 18+, его браузерный инспектор требует Node 22+
  и Chrome/Edge/Chromium. Проверь `node --version`; в Codex можно найти bundled
  Node через `load_workspace_dependencies`. Не меняй глобальный Node ради задачи.
- Impeccable содержит launcher; Windows использует `scripts/impeccable.cmd`.
  `${CLAUDE_SKILL_DIR}` в upstream означает абсолютную папку этого скилла,
  а не гарантированную переменную Codex. Подставь фактический путь. Launcher
  может скачать проверяемый по SHA-256 бинарник своей версии. При недоступности
  используй описанный upstream режим чтения контекста и разрешённые инструменты.
- Соблюдай ограничения браузерных инструментов текущей среды. Нельзя обходить
  их прямым CDP/скриптом Taste. При ограничении используй разрешённый браузер и
  ручную проверку по рубрике, сообщив, что автоматический инспектор не выполнен.

Готовый UI, доказательства и оставшиеся ограничения передай в финале по базе
`orchestrate`. Если задача затронула продуктовые контракты или backend, передай
эту часть в `develop-it`; дизайн сам по себе не разрешает деплой или публикацию.
