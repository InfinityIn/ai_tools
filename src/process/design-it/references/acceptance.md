# Приёмка дизайна

Используй только пункты, относящиеся к изменённой поверхности. Для audit-only
выход — находки и доказательства, а не исправленный интерфейс.

## Браузерная проверка

- Открой реальный URL/локальный preview. Запиши commit/diff, команду запуска,
  URL, браузер, размеры viewport и состояние данных, чтобы проверку повторили.
- Сними и посмотри desktop и mobile; при отсутствии требований начни с
  1440×900 и 390×844. Для промежуточного breakpoint используй 768×1024.
  Просмотри весь экран/страницу, включая footer, overlay и длинный контент.
- Пройди основной сценарий до наблюдаемого результата: кнопка, форма,
  переключение, навигация. Проверяй реальное поведение, а не наличие элемента.
  Внешние отправки, оплаты и публикации требуют соответствующего разрешения;
  для preview используй тестовые данные/среду и явно обозначай mock.
- Проверь клавиатуру и видимость фокуса; закрытие диалога и возврат фокуса;
  читаемость/контраст; перенос текста и отсутствие горизонтального overflow.
  Скриншот сам по себе не доказывает доступность.
- Для изменённых состояний проверь loading/empty/error/disabled/success.
  Не вводи фиктивные состояния в продукт ради чек-листа.
- Для motion проверь normal/reduced-motion, повторный быстрый запуск и отмену,
  touch/hover где применимо. Статический кадр не доказывает плавность;
  используй запись или последовательность кадров и наблюдение в браузере.
- Зафиксируй console/page errors и неуспешные запросы, отделяя дефекты изменения
  от ранее существующих/внешних. Запусти релевантные проверки самого проекта.

## Доказательства

В заметке сессии сохрани: критерий → действие/размер экрана → наблюдаемый
результат → путь скриншота/видео/лога. Не объявляй PASS без запуска.
Снимки и traces не должны содержать секреты или персональные данные; большие
бинарные артефакты размещай по правилам проекта, не коммить автоматически.

Если браузер недоступен: выполни доступные проверки кода, перечисли точно
непроверенное и дай воспроизводимый следующий шаг. Это частичная проверка,
не визуальная приёмка. После исправлений повтори затронутый сценарий с теми же
исходными условиями, сохранив исходный критерий.
