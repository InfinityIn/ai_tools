# Регламент проверки кода (код-ревью)

Корпоративный регламент проверки кода — приложение к справочнику
`../code-review.md`. Применяется, только если проект работает в этом
корпоративном контуре. Источник:
[Код-ревью](https://cfl.digtp.com/pages/viewpage.action?pageId=326701816) (Confluence).

> Импортировано из Confluence 2026-06-18. При расхождении — приоритет у Confluence.

## Общие положения

- Код-ревью проходит в **Bitbucket** на основании регламентов оформления кода
  (C# и TypeScript).
- Политика прохождения — **All reviewers approve** (одобряют все ревьюеры).
- Формат — **кросс-ревью** по таблице распределения «Распределение для кросс-ревью».
- Ревью проводят только разработчики того же направления (Backend ревьюит
  Backend, Frontend — Frontend и т.д.).

## Важные места при ревью (Backend)

1. `Appsettings`.
2. Чистая архитектура — структура проекта и зависимости в файлах `.csproj`.
3. Реализация интеграций — по чистой архитектуре, в папке модуля.
4. XML-документация кода.
