# Сборка (CI/CD) — артефакты этапа

Справочник этапа «Сборка». Рабочий контур — `develop-it`
(`src/process/develop-it/SKILL.md`); регламенты — R4.2 (гейт CI),
R5.1 (деплой), дополнительно R4.3 (сторожа и мутации),
см. `docs/regulations/README.md`.

Этот файл описывает, **что должно быть на выходе этапа**. Как вести сессию —
в профильном скилле, не здесь.

## Артефакты на выходе

| Артефакт | Файл | Обязателен |
|---|---|---|
| Отчёт по сборке | `output/build-report.md` | да |
| Причина сбоя со строкой лога | раздел отчёта | если сборка падала |
| Правки конфигурации пайплайна | репозиторий проекта | если решение требует правок |
| Запрос на недостающую выгрузку | текст запроса владельцу | если логов не хватает |

Вход этапа — **выгруженные логи сборки и деплоя**. Прямой доступ к CI/CD не
запрашивается: анализ идёт по логам, положенным в `inputs/`.

## Шаблон: build-report.md

```markdown
# Отчёт по сборке: <title>

## Статус сборки/деплоя
## Найденные ошибки
- <этап пайплайна> — <симптом> — <причина> — <строка лога как доказательство>
## Внесённые правки (если были)
## Риски применения (что сломается, если применить)
## Рекомендации по оптимизации CI/CD
## Что проверить после пересборки
```

## Формат разбора одного лога

Ответ по каждому логу или джобу — фиксированной формы:

- **причина** — одна фраза;
- **доказательство** — конкретная строка лога с номером или меткой времени;
- **кандидаты-фиксы** — 1–3 варианта с ценой каждого.

**Причина без строки лога — не причина, а догадка.** Первое сообщение об ошибке
важнее последнего: разбирать сверху вниз по времени, а не по последнему `ERROR`.

## Запрос недостающих логов

Если лога не хватает, запрос оформляется как постановка на выгрузку: **какой
джоб и шаг, диапазон времени, уровень логирования, в какой файл положить** и
**как проверить полноту** — начало и конец джоба на месте, лог не обрезан.
Ничего не додумывать за отсутствующий лог.

## Критерии приёмки этапа

- Каждая объявленная причина сопровождается **строкой лога**.
- Предложенное решение проверено вопросом **«что сломается, если это
  применить»**: другие джобы, кэш, матрица сборок, деплой, секреты, обратная
  совместимость. Неснятое возражение уходит в отчёт как риск.
- Выбор инструмента, версии экшена, образа или раннера подтверждён **живыми
  источниками** (≥2 независимых, со ссылкой и датой) — версии и лимиты не из
  памяти модели.
- Правки конфигурации внесены только после согласования; коммит и пуш — по
  явной просьбе.
- Раздел «Что проверить после пересборки» заполнен конкретными проверками.

## Что гейт обязан делать (R4.2)

Отчёт по сборке проверяет не только «позеленело», но и что гейт вообще способен
краснеть:

- гейт **безусловный**: без `paths:`-фильтров для тестов — иначе изменение вне
  фильтра проезжает мимо проверок;
- маркеры строгие (`--strict-markers` и аналоги) — опечатка в маркере не должна
  молча выключать тесты;
- **пол на число собранных тестов**: внезапное падение количества собранных
  тестов — красный, а не тишина;
- **список исключений пуст**: каждый «временно отключённый» тест — это дыра с
  датой смерти;
- деплой идёт **одним workflow**, и живой compose лежит там, где считает команда
  (R5.1).

## Типовые ошибки

- **Разбор по последнему ERROR.** Последняя строка — следствие; причина выше.
- **Причина «наверное, флака».** Без строки лога и без повторного прогона это
  догадка.
- **Фикс без вопроса «что сломается».** Починили джоб — уронили деплой.
- **Версия экшена из памяти.** Несуществующий тег ломает пайплайн второй раз.
- **Тесты за `paths:`-фильтром.** Гейт зелёный, потому что ничего не запускал
  (R4.2).
- **Обрезанный лог.** Вывод сделан по куску без начала джоба.
