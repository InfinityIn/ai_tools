# Регламент экспорта тест-кейсов в CSV

Приложение к справочнику `../test-design.md`: формат экспорта тест-кейсов в CSV
для импорта в системы управления тестированием (TestRail, Xray, QMetry и др.).

## Структура CSV-файла

### Заголовки столбцов

| Столбец | Тип | Обязательный | Описание |
|---------|-----|--------------|----------|
| `ID` | string | **да** | Уникальный идентификатор тест-кейса (например, `TC-001`) |
| `Name` | string | **да** | Краткое название тест-кейса |
| `Module` | string | да | Модуль системы (например, `01.BM Аутентификация`) |
| `Service` | string | да | Сервис системы (например, `01.01.BS Авторизация`) |
| `Function` | string | да | Функция системы (например, `01.01.01.BF Вход`) |
| `Type` | enum | **да** | Тип тестирования: `позитивный`, `негативный`, `граничный` |
| `Coverage` | enum | да | Тип сценария: `happy-path`, `альтернативный-сценарий`, `ошибка-восстановление` |
| `Level` | enum | **да** | Уровень тестирования: `unit`, `integration`, `e2e`, `manual` |
| `Priority` | enum | **да** | Приоритет: `critical`, `high`, `medium`, `low` |
| `Preconditions` | string | да | Предварительные условия |
| `Steps` | string | **да** | Шаги выполнения (каждый шаг с новой строки) |
| `ExpectedResult` | string | **да** | Ожидаемый результат (каждый результат с новой строки) |
| `TestData` | string | да | Тестовые данные (если применимо) |
| `RelatedReq` | string | да | Ссылки на требования (через запятую: `REQ-BUS-001,REQ-FUN-002`) |
| `Tags` | string | да | Теги через запятую (например, `authentication,smoke,regression`) |
| `Author` | string | да | Автор тест-кейса |
| `Status` | enum | да | Статус: `черновик`, `готов`, `утверждён` |

### Правила форматирования

1. **Кодировка:** UTF-8 с BOM (для корректного отображения кириллицы в Excel)
2. **Разделитель:** запятая (`,`)
3. **Кавычки:** двойные (`"`) — используются для экранирования полей, содержащих:
   - Запятые
   - Переносы строк
   - Кавычки (экранируются как `""`)
4. **Переносы строк внутри поля:** сохраняются как `\n` (в кавычках)

## Генерация из Markdown

При экспорте тест-кейсов из `test-cases.md` в `test-cases.csv`:

1. **Шаги:** Каждый шаг из таблицы превращается в отдельную строку (через `\n`)
2. **Ожидаемый результат:** Каждый результат — отдельная строка
3. **Связи с требованиями:** Извлекаются из поля `Связь с требованием/ТЗ`
4. **Теги:** Генерируются автоматически на основе типа, уровня и модуля

## Валидация

Перед экспортом проверить:

- [ ] Все обязательные поля заполнены
- [ ] ID уникальны
- [ ] Нет незакрытых кавычек
- [ ] Количество столбцов в каждой строке совпадает с заголовками
- [ ] Кодировка UTF-8 с BOM

## Использование в системах управления тестированием

### TestRail
- Импортировать через **Import → Test Cases → CSV**
- Маппинг столбцов настроить вручную (ID → Case Title, Steps → Steps, ExpectedResult → Expected Result)

### Xray (Jira)
- Импортировать через **Xray → Import → Test Import**
- Использовать шаблон Xray или адаптировать маппинг

### QMetry
- Импортировать через **Import → Test Cases**
- Поддерживает кастомные поля (Module, Service, Function)
