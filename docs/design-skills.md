# Направление «Дизайн»

Добавлено 2026-10-18. Входная точка — `design-it`; пять авторских прикладных
скиллов можно использовать и напрямую. Это набор для дизайна веб-интерфейсов,
включая анимации и проверку в браузере.

## Три слоя

Сохраняется модель **A — портфель / B — проект / C — сессия**.
Логический слой и физический каталог — разные вещи: профиль сессии C хранится
в общем репозитории A, чтобы переиспользоваться во всех проектах.

| Слой | Где находится дизайн | Что туда не переносим |
|---|---|---|
| A: портфель | `src/skills/` — пять переносимых инструментов, этот каталог источников и lock-файл; общие регламенты подключаются ссылками | Цвета бренда, продуктовые факты и стилевые запреты одного проекта |
| B: проект | Существующие документы бренда/дизайн-системы, токены, PRODUCT.md/DESIGN.md при необходимости, контракты, критерии конкретной задачи | Копии общих регламентов и глобальных скиллов |
| C: сессия | `src/process/design-it/` поверх `orchestrate`; бриф, маршрут, итерации и доказательства в заметке проекта | Постоянные правила, оставленные только в памяти сессии |

Новый слой `src/design/` не вводился. Справочники upstream остаются внутри
своих скиллов: они нужны при установке и имеют относительные ссылки. Отдельный
`src/references/` по правилам репозитория не устанавливается.

Impeccable взят из готового plugin bundle: включает reference/ и launcher со
своей версией engine, а не только короткий SKILL.md. Скопированы лицензии и NOTICE.
Для Emil выбран основной скилл автора: он уже включает кривые, длительности,
жесты, прерывание, производительность и доступность. Дополнительные навыки
для Swift/Expo и общие команды `animate` не устанавливались.

Единственная смысловая адаптация упаковки upstream: поля Impeccable `version`,
`user-invocable`, `argument-hint` перенесены в `metadata` для переносимого
frontmatter. Тело инструкции сохранено. Windows launcher имеет CRLF, shell
launcher — LF; это закреплено `.gitattributes`. Контрольные суммы нормализуют
CRLF/LF. Все остальные файлы сохранены из зафиксированных коммитов.

## Как работает оркестратор

Бриф и baseline → один арт-директор → реализация → анимация при необходимости
→ Impeccable для критики/полировки → Playwright для фактической приёмки.
Узкие задачи используют только нужные этапы.

- **Frontend Design** — основной выбор для экрана/компонента и рабочего UI.
- **Taste** — альтернативный арт-директор публичного сайта. Его текущая версия
  прямо исключает dashboards/app screens и требует Node 22+ для инспектора.
- **Impeccable** — `audit`, `critique`, `polish`, `adapt` и другие режимы; при
  задании «только аудит» не вносит изменения.
- **Emil** — выбор уместного движения и деталей взаимодействия.
- **Playwright** — реальный сценарий и изображения, а не решение, какой стиль красив.

Бриф и доступность важнее house style. Taste требует много изображений и движения,
а Emil рекомендует сдержанность в частых действиях. Оркестратор разрешает такой
конфликт до реализации, не смешивает две концепции и не меняет критерий ради PASS.

## Установка для новой сессии

Из корня ai_tools, PowerShell:

```powershell
$designSkills = @('design-it', 'orchestrate', 'frontend-design', 'impeccable',
                  'design-taste-frontend', 'emil-design-eng', 'playwright-cli')
./scripts/install.ps1 -Dest "$env:USERPROFILE/.agents/skills" -Only $designSkills
./scripts/install.ps1 -Dest "$env:USERPROFILE/.agents/skills" -Only $designSkills -Check
python scripts/check_design_skills.py --installed "$env:USERPROFILE/.agents/skills"
```

Для Claude Code замени назначение на `$env:USERPROFILE/.claude/skills`.
`-Only` устанавливает только перечисленные скиллы. Одноимённые каталоги
перезаписываются; локальные изменения перед повторной установкой сохрани отдельно.
Без `-Only` сохраняется прежняя установка всего набора. Bash installer также
видит новые скиллы при обычной установке всего набора.

Открой **новую сессию**, чтобы клиент перечитал каталог скиллов.

## Зависимости инструментов

Скилл Playwright не равен установленному CLI/браузеру. Без глобальной установки:

```powershell
npx --yes --package @playwright/cli@0.1.22 playwright-cli --help
npx --yes --package @playwright/cli@0.1.22 playwright-cli -s=design-check open http://localhost:3000 --browser msedge
npx --yes --package @playwright/cli@0.1.22 playwright-cli -s=design-check close
```

Порт бери из фактического preview проекта. Используй доступный браузер и
разрешённые инструменты среды. Не закрывай чужие сессии через `close-all`.

Taste: `draw.mjs` — Node 18+, `inspect.mjs` — Node 22+ и установленный
Chrome/Edge/Chromium. На проверенной машине системный Node — 20.2.0; bundled
Node Codex — 24.19.0. Его путь можно получить через `load_workspace_dependencies`.
Менять системный Node не требуется. Прямой CDP-инспектор Taste запускается только
там, где это разрешено браузерной политикой; иначе — разрешённый браузер и
ручная рубрика с явной отметкой, что инспектор не запускался.

Impeccable: Windows запускает `<skill>/scripts/impeccable.cmd`, POSIX —
`<skill>/scripts/impeccable`. Launcher скачивает engine указанной в `VERSION`
версии и проверяет SHA-256. `${CLAUDE_SKILL_DIR}` из текста заменяется реальным
абсолютным каталогом навыка. Бинарник хранится в пользовательском кеше, не в Git.
При недоступности engine upstream описывает режим работы без launcher.

## Проверка пакета и обновление

```powershell
python scripts/check_design_skills.py
```

Проверка выявляет пропажу, изменение и лишние файлы прикладных скиллов, а также
отсутствие `design-it`/`orchestrate`. Это контроль поставки, не оценка качества UI.
При обновлении сначала выбери новый upstream commit, сравни изменения и лицензии,
сохрани полный каталог навыка с зависимостями, повтори минимальные адаптации,
обнови lock-файл и прогони структурную проверку и smoke-тесты. Не обновляй SHA
после случайной локальной правки только ради зелёного результата.

## Запросы для испытания в отдельной сессии

1. `$design-it Сделай лендинг небольшой мастерской по брифу проекта. Сначала выбери визуальное направление, затем реализуй и проверь desktop/mobile.`
   Ожидается один арт-директор, конкретная композиция и реальные снимки результата.
2. `$design-it Отполируй текущую форму, сохрани бренд, поля и поведение.`
   Ожидается узкий Impeccable-проход без нового фреймворка или переписывания продукта.
3. `$design-it Добавь мягкое открытие drawer, повторное быстрое закрытие и reduced motion.`
   Ожидается Emil, прерываемый переход и проверка клавиатуры/фокуса.
4. `$design-it Только проверь этот экран, ничего не меняй.`
   Ожидаются находки со снимками/сценариями, без записи в исходники.
5. `$design-it Улучши плотную админку, не меняй фирменную фиолетовую палитру, анимации отключены.`
   Ожидается сохранение бренда, отсутствие Taste-маршрута и декоративного движения.

Сценарии подготовлены для следующей сессии. Структурные и инструментальные
проверки не означают, что оркестратор уже прошёл эти поведенческие испытания.
