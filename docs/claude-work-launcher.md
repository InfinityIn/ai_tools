# Запуск Claude Code: личный и корпоративный контуры

Дата: 2026-08-14.

## Схема разделения

| Контур | Как запускать | Какие настройки действуют |
|---|---|---|
| Личные проекты (F:\projects\…) | Claude Code **Desktop**, как обычно | глобальный `C:\Users\ncux2\.claude\settings.json` |
| Корпоративные (D:\work\…) | ярлык **«Claude Work»** на рабочем столе (CLI) | глобальный + поверх него `C:\Users\ncux2\.claude\1archive\settings.json` |

Корп-файл подключается флагом `--settings` — это отдельный слой настроек с приоритетом
**выше** глобального: его `env` (ANTHROPIC_BASE_URL / AUTH_TOKEN / MODEL) перекрывают
личные значения, поэтому CLI ходит через корпоративный gateway, а не через личный аккаунт.
Списки `permissions.allow` при этом складываются (глобальный allowlist действует и в
корп-сессиях; убрать конкретное правило для корп-контура можно, добавив его в
`permissions.deny`/`ask` в корп-файле).

## Что сделано

1. **Враппер**: [`scripts/claude-work.cmd`](../scripts/claude-work.cmd) — проверяет наличие
   корп-файла, переходит в `D:\work` (или в каталог из первого аргумента) и запускает
   `claude --settings "C:\Users\ncux2\.claude\1archive\settings.json"`.
2. **Ярлык**: «Claude Work» на рабочем столе → враппер, рабочая папка `D:\work`.

## Использование

- Двойной клик по «Claude Work» → консоль с Claude Code в `D:\work` на корп-настройках.
- Конкретный проект: `scripts\claude-work.cmd D:\work\ritmportal` — или скопировать ярлык
  и в свойствах дописать путь аргументом после имени `.cmd`.
- Проверка, что контур корпоративный: в сессии `/status` — модель `claude-opus-4-8`
  и корпоративный base URL.

## Замечания

- Токен лежит в `~/.claude/1archive/settings.json` — вне git-репозиториев, так и держать;
  в репо этот файл не коммитить.
- Ручной запуск без ярлыка (эквивалент):

```bash
claude --settings "C:/Users/ncux2/.claude/1archive/settings.json"
```
