# ADR — записи об архитектурных решениях

## Правило: ADR пишется ДО кода

Архитектурное решение фиксируется **до** реализации, а не задним числом. ADR задним числом
описывает не решение, а то, что случайно получилось, — и не решает ничего.

**PR с архитектурным решением без ADR не мержится.** Ревьюер вправе вернуть PR одной
строкой: «нет ADR».

Регламент — R2.2 в каталоге `ai_tools`:
[docs/regulations](https://github.com/InfinityIn/ai_tools/blob/main/docs/regulations/README.md).

## Когда нужен ADR

- Выбран каркас, хранилище, протокол, граница модуля или деплой-юнит.
- Решение трудно отменить или его отмена стоит больше сессии.
- Проект осознанно отклоняется от регламента R0–R7 (в том числе пропускает пункт дня 0 —
  тогда номер ADR указывается в `DAY0.md` как `[skip: ADR-nnnn]`).
- Решение придётся объяснять через полгода тому, кого не было в сессии.

Не нужен: выбор имени переменной, локальный рефакторинг, всё, что отменяется одним PR.

## Нумерация и файлы

`docs/adr/nnnn-slug.md`, где `nnnn` — сквозной номер с ведущими нулями (`0001`, `0002`),
`slug` — короткое имя в нижнем регистре через дефис: `0002-modular-monolith.md`.
Номера не переиспользуются; отменённый ADR остаётся в истории со статусом.

## Состояния

| Статус | Что значит |
|---|---|
| `proposed` | предложено, обсуждается; кода по нему ещё нет |
| `accepted` | принято, по нему пишется код |
| `superseded by ADR-nnnn` | заменено более поздним решением; текст не правится, ставится ссылка |
| `rejected` | рассмотрено и отклонено; остаётся как память о том, почему нет |

Принятый ADR не редактируется по существу: новое решение — новый ADR со ссылкой
`superseded by`. Правки допустимы только фактические (опечатка, битая ссылка).

## Как завести

Скопировать [0001-template.md](0001-template.md) в `nnnn-slug.md` и заполнить.
